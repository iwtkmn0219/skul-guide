# Skul 정리: 전체 재디자인 (2026-11-10)

디자이너 세션이 사용자와 회의해서 정한 디자인이다. 이 문서는 개발 계획을 세울 수 있을 만큼 구체적으로 쓴다. 지난 임시 시안(`docs/design/2026-11-10-hub-items/`)을 대체한다.

- 시안 화면: `screens/` (PNG), 직접 열어 보는 시안: `mockups/` (아래 "시안 파일" 참고)
- 시안의 HTML/CSS는 분위기와 배치를 보여 주기 위한 것이다. 그대로 옮기지 않아도 된다. 이 문서의 규칙이 우선한다.

## 1. 왜 바꾸나

사용자가 꼽은 문제 세 가지:

1. **게임과 거리감이 크다.** 흔한 정리 문서처럼 보여서 Skul의 도구라는 느낌이 없다.
2. **UI 크기가 제각각이다.** 특히 스킬 추천 페이지가 심하다. 카드가 같은 줄의 가장 긴 카드에 높이를 맞추기 때문에, 빌드가 2~4개인 스컬(8개) 옆의 짧은 카드에 큰 빈칸이 생긴다. 메모 수도 0~12개로 차이가 크다.
3. **찾아보기 어렵다.** 실제 사용 장면은 "PC에서 게임하다가, 방금 나온 아이템이나 새 스컬을 바로 찾아본다"이다. 지금은 허브에서 페이지 고르기 → 이동 → 검색창 클릭 → 입력을 거쳐야 하고, 스컬인지 아이템인지 헷갈리면 처음부터 다시 해야 한다.

## 2. 목표, 하지 않을 것, 실패로 볼 것

**목표**
- 사이트를 열면 바로 검색어를 칠 수 있다. 스컬, 아이템, 각인을 한 번에 찾는다.
- 마우스 없이 "열기 → 입력 → 방향키로 고르기 → 상세 읽기"가 된다.
- 같은 종류의 칸과 줄은 크기가 같다. 내용 양은 상세 칸이 흡수한다.
- 픽셀 + 마왕성 분위기로 게임과 같은 세계의 도구처럼 보인다.

**하지 않을 것**
- 게임 그림(로고, 캐릭터, 아이템 아이콘)을 저장소에 넣지 않는다. 돌벽과 횃불은 CSS로 직접 그린다.
- 밝은 화면(라이트 모드)은 만들지 않는다.
- 데이터 내용과 변환기(`tools/`)는 바꾸지 않는다. ★ / ◆ 설명 문구만 고친다(4장 9번).

**실패로 볼 것** (겉으로는 동작해도)
- 픽셀 분위기 때문에 글이 안 읽힌다(대비 부족, 너무 작은 글자, 흐릿한 글꼴).
- 칸 크기가 다시 들쭉날쭉해진다.
- 등급, 표시, 상태를 색으로만 구분한다.
- 예전 주소나 공유된 링크가 깨진다.
- 출처와 라이선스가 안 보인다.

## 3. 제약

- 정적 사이트, 빌드 없음, 런타임 의존성 없음. 외부 CDN을 쓰지 않는다. 글꼴 파일은 사이트 안에 넣는다.
- 360px 폭에서 페이지 전체 가로 스크롤이 생기지 않는다.
- 키보드만으로 모든 기능을 쓸 수 있고, 포커스가 눈에 보인다.
- `prefers-reduced-motion: reduce`이면 움직임을 멈춘다.
- 비상업. 광고 영역을 두지 않는다.
- 출처(디시 스컬 갤러리 원문, 나무위키 문서 7개)와 라이선스(CC BY-NC-SA 2.0 KR)를 화면에 보이게 둔다.

## 4. 사용자가 정한 것

1. **분위기:** `screens/02-castle.png`의 **3번 "설명 글까지 픽셀"**. 어두운 보라 돌벽 바탕, 양쪽 위의 횃불 빛과 픽셀 횃불, 보라색 픽셀 테두리(모서리가 깎인 각진 테두리)를 두른 어두운 정보 칸을 쓴다. 제목, 이름, 라벨, 설명 글까지 모든 글자를 픽셀 글꼴로 쓴다. 사용자 말: "확실히 게임스러워졌다."
2. **밝은 화면 없음.** 어두운 화면 하나만 둔다.
3. **글꼴 파일을 사이트에 넣는다.** 무료 픽셀 글꼴 "갈무리"(OFL-1.1)를 쓴다.
4. **사이트 전체를 화면 하나로 합친다.** 검색창, 그 아래 탭 "전체 · 스컬 · 아이템 · 각인", 목록과 상세로 구성한다. 허브 페이지와 상단 메뉴(홈 · 스킬 추천 · 아이템·각인)는 없앤다.
5. **열자마자 검색창에 포커스가 간다.** 어디서든 `/` 키를 누르면 검색창으로 간다(사용자 제안).
6. **스컬과 각인은 "목록 + 오른쪽 상세"로 보여 준다** (`screens/03-skills-layout.png`의 B). 목록 줄 높이는 모두 같다.
7. **아이템은 "같은 크기 그림 칸 격자 + 오른쪽 상세"로 보여 준다** (`screens/05-item-grid.png`의 A). 칸마다 그림 자리 아래에 이름과 각인을 둔다. 누르면 오른쪽에 상세가 나온다.
8. **아이템 그림:** 그림 자리를 만들어 둔다. 지금은 그림이 없으므로 등급 색 픽셀 틀 안에 글자를 넣어 채운다(9장). 실제 그림은 나중에 스컬 초상화와 같은 방식으로 넣을 수 있게 한다.
9. **★ = 신화 DLC, ◆ = 마석으로 해금되는 스컬.** 표시를 유지하고, 거르는 버튼("★만 보기", "◆만 보기")도 유지한다. 지금 문구 "원문 작성자가 스컬 이름에 붙인 표기입니다. 뜻은 원문에 적혀 있지 않습니다."는 틀렸으니 고친다.
10. **DLC 아이템(23개, `dlc: true`)도 신화 DLC다.** 스컬과 같은 "★ 신화 DLC" 표시를 쓴다. 지금의 "DLC" 배지를 대신한다.

## 5. 디자이너가 정한 것

사용자에게 설명했고 이의가 없었던 것:

- **강조색:** 횃불 주황(`--acc`)을 검색 일치 밑줄, 선택된 줄과 칸, 입력 커서에 쓴다.
- **등급 색:** 지금 등급 색 체계(일반, 레어, 유니크, 레전더리, 흉조)를 유지한다.
- **움직임:** 횃불 깜빡임만 둔다.
- **스킬 정보:** 각성 단계별 스킬 정보는 지금처럼 창(`dialog`)으로 띄우지 않는다. 스컬 상세 칸 아래에 이어서 보여 준다.
- **등급 구분:** 등급은 목록과 격자 안의 소제목으로 나눈다. 등급 탭은 없앤다.
- **아이템 상세:** 그 아이템 각인의 단계별 효과를 바로 보여 준다.
- **각인 상세:** "이 각인이 붙은 아이템"을 작은 칸으로 보여 주고, 누르면 그 아이템으로 넘어간다. 그래서 지금의 "각인: 전체 ▾" 선택 칸은 없앤다.
- **아이템 → 각인:** 아이템 상세의 각인 이름을 누르면 그 각인 상세로 넘어간다.
- **전체 탭:** 스컬은 목록, 아이템은 격자, 각인은 목록으로 각자 모양을 유지한 채 묶음으로 보여 준다. 처음 열면 전체 탭이다.
- **휴대폰:** 아이템은 한 줄에 2칸이다. 고르면 상세가 화면을 덮고, "◀ 목록"이나 뒤로 가기로 돌아온다. 탭은 두 줄로 내려가도 된다.
- **예전 주소:** `/skills/`와 `/items/`로 들어오면 새 화면의 해당 탭으로 옮긴다.

사용자에게 아직 설명하지 않은 세부 결정(문서를 넘길 때 함께 확인받는다)은 6~10장 곳곳에 **(디자이너 판단)**으로 표시했다.

## 6. 화면 구성

### 6.1 데스크톱 (761px 이상)

```
┌───────────────────────────────────────────────────────────────┐
│ 🔥 Skul 정리 🔥   [⌕ 검색어 ……………………………………………… [/]]          │ 머리 띠
│ [전체 339] [스컬 45] [아이템 258] [각인 36]   (스컬 탭: [★ 신화 DLC] [◆ 마석 해금]) │
├──────────────────────────────┬────────────────────────────────┤
│ 목록 또는 격자 (따로 스크롤)  │ 상세 (따로 스크롤)              │
│  ■ 일반 13                    │  종류 · 분류                    │
│  ▌웨어울프  사냥 + 짐승의 도약 │  이름  [등급] [★ 신화 DLC]      │
│  …                            │  …                              │
├──────────────────────────────┴────────────────────────────────┤
│ 비공식 팬 정리 · 권리는 SouthPAW Games · 출처 … · CC BY-NC-SA 2.0 KR │ 바닥 띠 (항상 보임)
└───────────────────────────────────────────────────────────────┘
```

- 칸 비율: 스컬·각인은 목록 5 : 상세 6, 아이템은 격자 6 : 상세 5.
- **(디자이너 판단)** 화면 높이에 맞춘 앱형 배치로 만든다. 머리 띠와 바닥 띠는 고정하고, 목록과 상세는 각자 스크롤한다. 긴 목록을 내려도 상세와 출처가 계속 보인다.
- 아무것도 고르지 않았을 때(처음 열었을 때) 상세 칸에는 짧은 안내를 둔다. 예: "목록에서 고르면 여기에 나옵니다. `/` 검색 · `↑↓` 이동". **(디자이너 판단)**

### 6.2 머리 띠

- 왼쪽에 사이트 제목 "Skul 정리"와 양옆 픽셀 횃불을 둔다. `<title>`은 지금처럼 "Skul: The Hero Slayer 정리"로 한다.
- 검색창은 남은 폭을 다 쓴다. 오른쪽 끝에 `/` 키 표시를 붙인다. placeholder에는 검색 대상(이름, 효과)을 적는다.
- 검색창에 포커스가 있으면 테두리를 주황 픽셀 테두리로 바꾼다. 입력 커서는 `caret-color: var(--acc)`로 칠한다.

### 6.3 탭

- "전체 · 스컬 · 아이템 · 각인" 탭마다 지금 검색어 기준 결과 수를 붙인다.
- 결과가 0인 탭은 흐리게(불투명도 .55) 표시하되 누를 수는 있다.
- 선택된 탭은 뼈 색 바탕(`#f3ead6`)에 어두운 글자로 표시한다.
- 탭을 바꿔도 검색어는 유지한다.
- **(디자이너 판단)** 탭마다 마지막으로 고른 항목을 기억한다. 탭을 오가도 각 탭의 상세가 그대로 남는다.
- **스컬 탭에서만** 탭 줄 오른쪽에 "★ 신화 DLC", "◆ 마석 해금" 거르기 버튼을 둔다. 지금의 `data-mark` 동작(누르면 켜짐, 다시 누르면 꺼짐, `aria-pressed`)을 그대로 쓴다.
  - **(디자이너 판단)** 이 거르기는 스컬 탭에만 적용한다. 전체 탭에는 적용하지 않는다. 버튼이 보이지 않는 곳에서 결과가 몰래 줄어들지 않게 하기 위해서다.
- **(디자이너 판단)** 전체 탭의 묶음 순서는 스컬 → 아이템 → 각인이다.

### 6.3-1 검색하는 동안 고르기

- **(디자이너 판단)** 데스크톱에서는 검색어가 바뀌면, 현재 탭의 첫 결과를 자동으로 고른다. 그러면 오른쪽 상세가 바로 바뀐다. 그래서 "칼레온 계급"까지 치면 방향키 없이도 상세가 보인다. 포커스는 검색창에 남겨 둬서 계속 칠 수 있게 한다.
- 휴대폰에서는 자동으로 고르지 않는다. 상세가 화면을 덮기 때문이다.
- 검색어가 비면 자동 선택을 하지 않고, 이전에 고른 항목을 유지한다.

### 6.4 스컬 목록

- 등급 소제목: "■ 일반 13"처럼 등급 색 네모, 등급 이름, 개수를 쓴다.
- 줄 높이는 42px로 고정한다. 한 줄에 다음을 넣는다.
  - 원문 번호(작게)
  - 이름(굵게). ★/◆가 있으면 이름 뒤에 기호를 붙이고, 기호에는 `title`과 접근성 이름("신화 DLC", "마석 해금")을 준다.
  - 대표 조합(작게): 첫 빌드의 슬롯을 "사냥 + 짐승의 도약"처럼 쓴다. 빌드가 2개 이상이면 뒤에 "· 빌드 2"를 붙인다. 추천이 없으면 "추천 없음"이라고 쓴다.
- 칸이 좁으면 대표 조합부터 말줄임(…) 처리한다. 이름은 줄이지 않는다.
- 등급 소제목이 없는 곳(전체 탭의 섞인 결과)에서는 줄 오른쪽 끝에 등급 글자("일반")를 붙인다. 색으로만 등급을 나타내지 않기 위해서다.

### 6.5 아이템 격자

- 칸은 `minmax(148px, 1fr)`로 자동 배치하고, 높이는 172px로 고정한다.
- 칸 안의 구성은 위에서부터 다음과 같다.
  1. 그림 자리: 64×64px. 등급 색 3px 픽셀 테두리, 안쪽은 어두운 원형 그라데이션이다.
  2. 이름: 최대 두 줄, 넘치면 말줄임, 가운데 정렬.
  3. 각인 두 개: 작은 칩으로 칸 아래쪽에 붙인다.
- 신화 DLC 아이템은 그림 자리 오른쪽 위에 작은 "★" 표를 붙인다. `title`과 접근성 이름은 "신화 DLC"로 한다. 스컬 목록 줄의 ★과 같다. **(디자이너 판단: 위치)**
- 무작위 각인(`랜덤`, `랜덤A`, `랜덤B`)은 점선 테두리의 흐린 칩으로 표시한다. 누를 수 없다. 지금과 같다.
- 선택된 칸은 주황 테두리와 어두운 갈색 바탕(`#3a1f12`)으로 표시한다.
- 등급 소제목은 스컬 목록과 같고, 일반 → 레어 → 유니크 → 레전더리 → 흉조 순서다.

### 6.6 각인 목록

- 분류 소제목: 능력치 각인, 상태이상 각인, 특수능력 각인(공격), 특수능력 각인(방어). 분류마다 개수를 붙인다.
- 줄에는 이름(굵게)과 오른쪽 끝의 "개조 가능" 또는 "개조 불가"를 넣는다. 개조 불가인 각인은 죄, 흉조, 걸작, 해와 달이다.

### 6.7 상세 칸

모든 종류에 공통으로, 맨 위에 종류(아이템, 스컬, 각인) 작은 라벨을 두고 그 아래에 이름(22px)과 배지를 둔다.

**스컬 상세**
- 이름, 등급 배지, ★/◆ 배지("★ 신화 DLC", "◆ 마석 해금")
- 빌드마다 점선으로 나눈 칸을 둔다. 칸에는 빌드 이름 태그(물리/마딜 등), 슬롯 칩(`+`로 잇고 대안은 `/`), 고정 스킬, "아무거나" 칩(점선), 메모 전부(글머리표)를 넣는다.
- "그 외" 칩(`pool`)을 둔다.
- 스킬 정보: 지금 `renderSkillDialog`의 내용(각성 단계 탭, 패시브, 교대, 스킬 표, 추천 표시)을 상세 칸 아래에 이어서 넣는다. 단계 탭은 픽셀 탭 모양으로 만든다.

**아이템 상세**

**각인 상세**

### 7.3 픽셀 테두리

모서리가 깎인 각진 테두리는 `box-shadow` 네 방향으로 만든다. 레이아웃 공간을 차지하지 않으므로 바깥 여백(`margin: 3px`)을 둔다.

```css
.frame { margin: 3px; box-shadow: 0 -3px 0 0 var(--frame), 0 3px 0 0 var(--frame), -3px 0 0 0 var(--frame), 3px 0 0 0 var(--frame); }
.frame-sm { box-shadow: 0 -2px 0 0 var(--c), 0 2px 0 0 var(--c), -2px 0 0 0 var(--c), 2px 0 0 0 var(--c); } /* 칩, 탭, 배지 */
```

- 정보 칸(검색창, 목록, 상세, 아이템 칸)은 3px, 작은 요소(칩, 탭, 키 표시)는 2px다.
- `border-radius`는 쓰지 않는다. 모두 각지게 한다.

### 7.4 돌벽과 횃불

- 돌벽: 32px 타일 SVG를 CSS 안에 `data:` URI로 넣는다. 위에 어둡게 하는 그라데이션과 양쪽 위 횃불 빛 두 개(`radial-gradient`, 주황 .28)를 겹친다. 시안 `mockups/unified.html`의 `.u` 배경을 참고한다.
- 횃불: 3px 한 칸짜리 픽셀 그림을 `box-shadow`로 그린다. 불꽃 7칸과 손잡이 3칸이고, `drop-shadow`로 빛을 낸다. 시안의 `.torch::before`를 참고한다.
- 움직임: 횃불만 `steps(2)`로 0.6초 깜빡인다. `prefers-reduced-motion: reduce`이면 멈춘다. 다른 움직임(카드 들썩임, 미끄러짐)은 넣지 않는다.

## 8. 키보드와 접근성

| 키 | 동작 |
|---|---|
| (열자마자) | 검색창에 포커스 |
| `/` | 검색창으로 가서 검색어 전체 선택. 단, 입력칸에서 글자를 치는 중이면 그냥 `/`가 입력된다 |
| 글자 입력 | 결과가 바로 줄어들고, 탭마다 개수가 갱신된다 |
| `↓` (검색창에서) | 결과 첫 항목을 고른다 |
| `↑` `↓` | 목록에서 이전·다음 항목. 고르는 즉시 상세가 바뀐다 |
| `←` `→` `↑` `↓` | 아이템 격자에서 칸 이동(위아래는 한 줄씩) |
| (묶음 경계) | 전체 탭에서는 화면 순서대로 이어진다. 스컬 목록 마지막 줄에서 `↓`를 누르면 아이템 격자 첫 줄로, 격자 마지막 줄에서 `↓`를 누르면 각인 목록 첫 줄로 간다. **(디자이너 판단)** |
| `Enter` | 상세 안의 링크와 칩에서 이동(각인 칩 → 각인, 아이템 칸 → 아이템) |
| `Esc` | 검색어가 있으면 지운다. 휴대폰에서 상세가 열려 있으면 목록으로 돌아간다 |

- 포커스 고리: `outline: 2px solid var(--focus); outline-offset: 5px;`. 픽셀 테두리(3px) 바깥에 보이게 하고, 선택 표시(주황)와 색을 다르게 한다. **(디자이너 판단)**
- 목록과 격자는 "고른 항목"과 "키보드 포커스"를 같은 것으로 다룬다. 구현 방식(roving tabindex 또는 `aria-activedescendant`)은 개발자가 정한다.
- 탭은 `role="tablist"`/`tab` 또는 `aria-pressed` 버튼으로 만든다. 결과 수 변화는 지금처럼 `aria-live="polite"`로 알린다.
- 색으로만 구분하지 않는다.
  - 등급: 소제목 글자, 또는 줄 끝 등급 글자
  - 선택: 바탕색과 주황 테두리, 왼쪽 막대
  - 개조 행: "n개 개조" 글자
  - 무작위 각인: 점선 테두리, `title`
  - ★/◆: 기호 모양과 글자
- 검색 일치 표시: 일치한 글자에 주황 2px 밑줄(`text-underline-offset: 4px`)을 긋는다. `<mark>`를 쓰고 배경은 없앤다.
- `color-scheme: dark`

## 9. 아이템 그림 자리

- 지금은 그림이 없으므로 그림 자리에 **이름 마지막 낱말의 첫 글자**를 등급 색으로 넣는다. "흉조: " 접두어는 빼고 센다. 예: 칼레온 계급장 → "계", 보급형 칼레온 검 → "검".
  - 알려 둘 약점: 258개 중 서로 다른 글자는 139개라 겹치는 일이 많다(가속검, 가시견갑, 가시장화가 모두 "가"). 아이템 구분은 아래 이름이 하고, 글자는 등급 색을 보여 주는 장식이다. 사용자에게 설명했다.
  - 글자 칸은 장식이므로 `aria-hidden="true"`를 준다.
- 나중에 그림을 넣는 방식은 스컬 초상화와 같다. 저장소에 넣지 않는 폴더(`.gitignore`)에 `{아이템 id}.png`를 두고, 설정을 켜면 그림을 보여 준다. 그림을 불러오지 못하면 글자로 돌아간다. 아이템에는 지금 id가 없으므로 id를 정하는 규칙은 개발자가 정한다.

## 10. 주소, 상태, 예전 링크

- 새 화면은 `/` 하나다. 탭, 검색어, 고른 항목, ★/◆ 거르기를 주소의 해시에 담아 공유와 새로고침, 뒤로 가기가 되게 한다. 해시 형식은 개발자가 정한다.
- 예전 주소는 모두 새 화면으로 옮긴다.
  - `/skills/` 및 `/skills/#grade=…&mark=…&q=…&skull=…` → 스컬 탭(검색어, 표시, 고른 스컬 유지. `grade`는 버린다)
  - `/items/#view=items|engravings&grade=…&eng=…&q=…` → 아이템 또는 각인 탭. `eng`가 있으면 그 각인을 고른 상태로 연다.
  - 루트 시절 해시(`legacy-redirect.js`가 처리하던 `/#grade=…` 등)도 계속 동작해야 한다.

## 11. 개발자에게 맡기는 것

- 데이터 묶기, 검색 규칙. 지금 `filter.js`와 `item-filter.js`의 일치 규칙을 그대로 쓰고, 스컬은 이름과 스킬, 아이템과 각인은 이름과 효과를 찾는다. 결과 순서도 정한다.
- 글꼴 서브셋 방법과 범위(데이터와 UI 문구에 쓰인 글자, 또는 KS X 1001 한글 2,350자 + ASCII 등). Bold 파일이 다루는 글자 범위가 일반 파일과 다를 수 있으니, 데이터의 이름에 빠지는 글자가 없는지 확인한다.
- 목록과 격자의 렌더링 방식, 성능(전체 탭에서 339개)
- 해시 형식, 예전 링크 옮기기 구현
- 결과가 없을 때의 문구(다른 탭에 결과가 있으면 그 탭을 알려 주기 권장)
- 테스트 갱신
